## 2. v0.3 주경로 (날짜 기준) — `schedule.py` + 보기 ④ 탭

엑셀에 적힌 날짜를 그대로 놓고 잰다 (사람들이 보는 일정표와 같은 기준). 지금까지의 '가장 긴 사슬'(기간 합, 날짜 안 씀)은 내부 계산·TTL 에만 남기고 화면·보고서에서는 뺐다.

- **시간 축 = 평일 번호** (월~금, 휴일·사내 달력 모름 — 근사). 시작 사건 = 그 날 아침, 완료 사건 = 그 날 저녁, 마일스톤 = 그 날 저녁 하나.
- **선행 간격** = 후속 쪽 사건 − 선행 쪽 사건 − 지연 (FS 완료→시작 · SS 시작→시작 · FF 완료→완료 · SF 시작→완료). 0 = 빡빡(구동), 양수 = 여유, 음수 = 날짜가 선행을 어김 (C05 와 같은 것).
- **총 여유** = 늦은 시작 − 실제 시작. 늦은 값은 사업 마지막 완료에서 거꾸로 (기간·지연만). 요약 작업 = 그 아래 하위 업무 여유의 최소.
- **주경로** = 총 여유 ≤ 0 (설정 `critical_float_days`), **준주경로** = ≤ 5 평일 (설정 `near_critical_days`).
- **다음 경로 여유** = 주경로 밖 하위 업무 중 가장 작은 여유 → 주경로를 이보다 더 줄이면 다른 경로가 주경로가 된다 (단축 한계의 첫 눈금).
- 날짜 없는 하위 업무·시작 > 완료는 계산에서 빠짐. 순환 간선은 뺌.
- 보기 HTML 의 JS 가 같은 규칙으로 다시 계산해 파이썬 값(업무 여유·선행 간격)과 대조 — ④ 탭 아래 '일치 ✓'.

화면:
- **④ 주경로 탭** — 사업 기간·주경로/준주경로 수·다음 경로 여유 · 왼쪽 '어디가 일정을 쥐고 있나'(구성품/최상위/단계/분야/상위 업무별 주경로 평일 합, 누르면 목록 거름) · 오른쪽 주경로 목록(시작 순, 총 여유·MH·**구동 선행**) · 기준 입력칸 · '간트에서 보기'.
- **간트** — 막대 빨강 = 주경로, 노랑 = 준주경로 ('주경로 색' 켜고 끔), 왼쪽 표 '여유' 열, 빠른 보기 **'주경로만'**(주경로·준주경로 하위 업무만, 줄 = 개발 단계, 시작일 순).
- **패널** — 총 여유, 주경로/준주경로 표시, 선행 목록에 '구동'/'간격 n'.
- 보고서 **'주경로' 시트**(순서·구분·날짜·평일·총 여유·MH·구동 선행) · '업무' 시트 '선행 중 최소 간격'·'총 여유'·'주경로(●/○)' · 단계·분야 요약에 '주경로 하위 업무'·'최소 여유' · TTL derived `wbs:dateFloatDays`·`onCriticalPath`·`nearCriticalPath`·`gapDays` · run_log `critical_path`(숫자만).

합성 데이터: 묶음 안에 **나란한 두 업무**(뒤 업무가 둘 다 기다림)를 섞어 준주경로가 생기게 했다.

## 3. v0.4 가정 편집 (설계)

**흐름**: 보기에서 고침 → 바로 다시 계산(날짜·주경로·완료일) → '변경 목록 내려받기'(.json) → `apply`(원본 엑셀 + 변경 목록) → **`<원본>_수정_v01.xlsx`** (원본 형식 그대로, 원본은 안 건드림, 판 번호 증가) → 그 파일로 다시 build.

**고칠 수 있는 것 (v0.4)**: 하위 업무의 기간(평일) · 시작(이 날 이후) · 모든 업무의 선행(MS Project 표기 그대로 `12,15SS+5일`) · 이름 · Man Hours · 투입인력.
**아직 안 하는 것**: 행 추가·삭제·이동(번호·WBS 코드 다시 매기기) — 이 도구가 주 편집기가 되면 필요. v0.5 이후 따로 설계.

**다시 짜기 규칙 ('간격 유지')** — 고치지 않으면 날짜가 하나도 안 바뀌어야 한다:
- 업무마다 원래 날짜에서 잰 선행 간격을 안다.
- 선행에 **구동된**(간격 ≤ 0 인 선행이 있는) 업무 → 새 시작 = 선행이 요구하는 날짜의 최대 (선행이 당겨지면 같이 당겨짐).
- 구동되지 않은(모든 선행에 여유가 있는) 업무 → 새 시작 = max(원래 시작, 선행 요구) — 여유를 다 쓰기 전엔 그대로, 넘치면 밀림. 손으로 늦게 잡은 날짜(제약)로 본다.
- 원래 음수 간격(선행 어김)은 그만큼 느슨하게 둔다 (고치지 않으면 안 움직이게).
- 선행이 없는 업무는 그대로 (시작을 고치면 그 날).
- 완료 = 시작 + 기간(평일). 요약 작업 = 하위 범위로 다시 (엑셀 요약 날짜가 원래 하위 범위와 같았던 것만 새로 씀 — C11 인 것은 그대로 두고 알림).
- 파이썬(`apply`)과 JS(보기)가 같은 규칙 — 변경 목록에 JS 결과 날짜를 함께 넣어 `apply` 가 대조한다.

**쓰기 형식**: 바뀐 칸만 고친다 (openpyxl 로 원본을 열어 셀 값만 — 서식·다른 시트 유지). 날짜는 원래 칸 모양(글자 `27-01-01 (금)` 이면 같은 모양, 날짜 셀이면 날짜), 기간은 원래 단위 글자(`10 일`), 선행은 원래 표기 습관(한글 `완시` 등)을 따름, 후속 열(H)이 있으면 영향받은 행만 다시 씀.
**안전**: 변경 목록에 원본 sha256 을 넣어 다른 판 엑셀에 적용하지 않음 · 원본 덮어쓰기 금지 · 인명 칸은 읽지도 쓰지도 않음.

## 4. '아예 SW 로 개발할까' (Leo 질문)

**권장: 지금 방식(파이썬 엔진 + 한 장 HTML)으로 v0.4 까지 가고, 이 도구가 실제 주 편집기로 쓰이기 시작하면 그때 '로컬 웹 앱'으로 올린다.**

- 지금 구조가 이미 SW 의 뼈대다: 엔진(읽기·검사·일정 계산·쓰기)과 화면이 나뉘어 있고, 둘이 같은 규칙을 서로 대조한다. 반입 0·설치 0 이 큰 장점.
- 주 편집기가 되면 생기는 요구 — 행 추가·삭제, 여러 사람이 고침, 누가 언제 무엇을 고쳤는지(판 이력), 바로 저장 — 는 한 장 HTML 로는 어렵다. 그때 **표준 라이브러리 `http.server` 로컬 웹 앱**(127.0.0.1, 같은 화면 + 저장 API, 반입 0)으로 옮기고, 판 이력은 엑셀 판 파일 + 변경 목록 JSON 쌓기로 시작.
- 정식 SW 개발로 갈지는 '누가 쓰나(혼자/팀/사업 전체)'·'MS Project 를 계속 쓰나'·'사내 배포 방식' 이 정해져야 한다 — 그 결정이 먼저. 그 전에 요구사항 문서 한 장을 같이 쓰는 것을 권한다.

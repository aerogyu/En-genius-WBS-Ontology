# WBS 도구 아키텍처 설계 v0.5 (제안, 2026-11-12)

요구사항은 `docs/04`. Leo 답 (2026-11-12): **A** 정본을 도구 DB 로 옮김 · **B** 이력은 역할 단위 · **C** 사내 계정 연동 · **D** 서버 PC 에 WBS 를 둠(전부 방산망 안) ·
**E** 모듈 = Lv1 구성품, 모듈 리더 10~15명 (공통 모듈 권한은 답 없음 → 3장 기본값).
이 문서는 **제안**이다 — 9장의 확인 질문에 답을 받은 뒤 구현한다.

## 1. 한 장 요약

```
 브라우저 (20~30명, 사내망)                서버 PC (상시 켜 둠, 한 대)
 ┌──────────────────────┐   HTTP    ┌──────────────────────────────────────┐
 │ 화면 (지금 보기 HTML  │ ───────▶ │ 웹 서버 (starlette + uvicorn)         │
 │  을 나눠 옮긴 것)     │  JSON    │  ├ 로그인·권한 (auth)                 │
 │ JS 일정 엔진 = 미리  │ ◀─────── │  ├ 저장 (store) ── SQLite 파일 1개    │
 │  보기 (저장 전)       │          │  ├ 기존 엔진 (검사·주경로·다시 짜기)  │
 └──────────────────────┘          │  └ 엑셀·보고서·TTL 내보내기           │
                                    └──────────────────────────────────────┘
```

DB 비유: 지금까지는 '엑셀 파일 = 데이터, 도구 = 보고서 생성기' 였다. 이제 **SQLite = 정본 DBMS, 서버 = 앱, 엑셀 = 들여오기·내보내기 형식**이 된다.

- 프로세스 1개, 파일 1개(SQLite, 표준 라이브러리). 설치는 지금처럼 폴더 + `.bat`.
- 새 반입 **0 을 목표**: starlette·uvicorn 은 Tool 온톨로지 MCP 묶음에 이미 있다 (개발 PC 1.7.0 / 0.54.0, BSD). 사내 묶음의 판은 다를 수 있어 확인 필요 (9장 Q5).
- 계산은 **서버(파이썬)가 정본**, 브라우저(JS)는 저장 전 미리 보기 — v0.4 에서 검증한 '두 엔진 대조' 구조를 그대로 쓴다.

## 2. 데이터 모델 (SQLite)

### 2-1. 핵심 생각: 번호와 WBS 코드는 '계산값' 이 된다

지금 엑셀은 번호(A열)가 곧 ID 라 행을 넣으면 선행이 깨진다. DB 에서는 업무마다 **바뀌지 않는 uid** 를 주고,
번호·WBS 코드·레벨은 **트리에서의 위치로 매번 계산**한다. 행을 넣고 빼도 선행 연결(uid ↔ uid)은 그대로다.

| 표 | 주요 열 | 뜻 |
|---|---|---|
| `task` | `uid`(영구, 재사용 안 함) · `parent_uid` · `pos`(형제 순서) · `name` · `duration_days`·`duration_unit` · `start_floor`(이 날 이후, 없을 수 있음) · `start`·`finish`(계산 결과 보관) · `staff` · `man_hours` · `deliverables` · `module_uid`(Lv1 조상) · `deleted` · `rev` | 업무 한 줄. 요약인지는 자식이 있는지로 안다 |
| `dep` | `succ_uid` · `pred_uid` · `type`(FS·SS·FF·SF) · `lag_days`·`lag_text` · `relax_days` | 선행 연결. 후속 업무의 소유 |
| `txn` | `id` · `ts` · `actor`(역할 이름) · `summary` · `rev` | 저장 한 번 = 한 묶음 |
| `change` | `txn_id` · `task_uid` · `field` · `old` · `new` | 무엇이 어떻게 바뀌었나 (지우지 않고 쌓기만) |
| `request` | `id` · `from_role` · `to_module` · `task_uid`(없을 수 있음) · `text` · `status`(열림·처리·반려) · `ts`·`closed_ts` · `note` | 수정 요청 |
| `snapshot` | `id` · `label`('1차본') · `ts` · `note` · `payload`(전체 업무·선행 압축 JSON) | 판 확정 — 그대로 얼린 사본 |
| `role` | `id` · `label`('FAN 리더') · `kind`(관리자·리더·조회) · `module_uid` | 역할 |
| `login` | `account`(사내 계정 ID) · `role_id` | 사내 계정 → 역할 (서버 DB 에만, 4장) |
| `meta` | 스키마 판 · 원본 엑셀 sha256·머리글 모양 · 설정 | |

### 2-2. 날짜 모델 — '간격 유지' 를 데이터로 굳힌다

v0.4 의 '간격 유지' 는 "엑셀 날짜 중 어느 것이 손으로 잡은 날짜인지 모른다" 는 사정 때문에 매번 원래 간격을 다시 재는 규칙이었다.
정본이 DB 가 되면 **들여올 때 한 번만 재서 데이터로 남긴다** — 이후는 평범한 일정 계산(앞에서부터 밀기)이다.

- 하위 업무의 시작 = max(`start_floor`, 선행들이 요구하는 날짜). 완료 = 시작 + 기간. 요약 = 하위 범위 (늘 계산 — 요약 날짜 불일치 C11 은 생길 수 없게 됨).
- **들여오기 때**: 선행에 구동되던 업무(간격 0 이하)는 `start_floor` 없음 · 여유가 있던 업무는 `start_floor` = 원래 시작 (손으로 잡은 날짜로 봄) ·
  날짜가 선행을 어기던 연결(C05)은 어긴 만큼을 `relax_days` 에 적는다 → **들여온 직후 날짜가 하나도 안 움직인다** (v0.4 와 같은 보장, 테스트로 고정).
- `relax_days` 가 남은 연결은 검사 목록에 계속 뜬다. 누가 '바로잡기' 를 누르면 0 이 되고 그때 날짜가 밀린다 — 어긋난 일정을 조용히 고치지 않고 사람이 정한다.
- 선행을 지워 구동이 없어지면 그 업무의 `start_floor` 를 지금 시작으로 채운다 (v0.4 '지워도 저절로 당겨지지 않음' 과 같은 동작).
- 휴일 달력(2단계)은 평일 번호 함수 한 곳만 바꾸면 되게 둔다.

### 2-3. 기존 엔진 재사용

서버는 DB 에서 읽어 **지금의 `Wbs`/`Task` 객체**(번호는 현재 순서로 매김)를 만들고 `analyze`·`schedule`·`report`·`rdfout` 을 그대로 부른다. 엔진은 거의 안 고친다.
실측(합성 12,827행, 개발 PC): 검사·주경로 1.2초 + 다시 짜기 0.7초 → **저장 한 번에 약 2초**. 20~30명·저장 빈도로는 충분하다고 보지만, 답답하면 바뀐 부분만 다시 계산하도록 나중에 고친다 (지금은 단순함을 택함).

## 3. 권한

| 동작 | 관리자 | 모듈 리더 | 조회자 |
|---|---|---|---|
| 보기·검색·내려받기 | ○ | ○ | ○ |
| 자기 모듈 업무 고치기·추가·삭제·모듈 안 이동 | ○ | ○ | – |
| 자기 업무의 선행으로 **다른 모듈 업무를 고름** | ○ | ○ (자기 업무를 고치는 일이므로) | – |
| 다른 모듈 업무 고치기 | ○ | – → **수정 요청** | – |
| Lv1 구성품 추가·삭제, 모듈 사이 이동, 판 확정, 역할 관리, 들여오기 | ○ | – | – |

- 규칙 한 줄: `관리자이거나 업무의 module_uid = 내 역할의 module_uid`. 서버가 저장 때마다 검사한다 (화면에서 숨기는 것은 편의일 뿐).
- **공통 모듈**(체계종합 등): 역할을 따로 주기 전에는 관리자만 고친다. 어느 Lv1 이든 리더 역할을 만들면 그때부터 그 리더가 고친다.
- 내가 기간을 늘리면 **남의 모듈 날짜가 밀릴 수 있다** — 막지 않는다 (그게 일정의 사실이므로). 대신 저장 전에 '다른 모듈 n개 업무가 밀림 · 사업 완료 +n일' 을 보여 주고, 밀린 모듈에는 '내 모듈에 생긴 변화' 로 알린다.

## 4. 로그인 — 사내 계정 연동 + 역할 단위 이력

- **구조**: `auth` 를 갈아 끼우는 부품으로 둔다. ① 개발·비상용: 도구가 발급한 역할 계정(비밀번호는 표준 라이브러리 PBKDF2 해시) ② 사내 계정 연동 어댑터.
- **사내 연동 방식은 사내가 무엇을 제공하느냐에 달렸다** (9장 Q1). 경우별 판단:
  - OIDC/OAuth 인증 서버가 있다 → 표준 라이브러리 `urllib` 로 붙일 수 있을 것으로 봄 (새 반입 0 가능, 확인 필요).
  - Windows 통합 인증(로그인한 PC 계정 그대로) → 추가 라이브러리가 필요할 수 있음 (반입 검토).
  - En-genius 플랫폼의 로그인을 빌려 씀 → 플랫폼 개발자에게 방법 확인.
  방식이 정해질 때까지 ①로 개발·시험하고, 어댑터만 나중에 붙인다 — 나머지 설계는 영향받지 않는다.
- **B(역할 단위)와 C(사내 계정)의 접점**: 사내 계정 ID → 역할 표(`login`)는 **서버 DB 에만** 있고 관리자 화면에서만 고친다.
  이력·수정 요청·내보낸 엑셀·TTL·실행 로그에는 **역할 이름만** 남는다 ('FAN 리더'). 저장소·반출물에는 계정 ID 가 들어가지 않는다.
  관리자 3~4명을 이력에서 구분하려면 역할을 '관리자 1·2·3' 처럼 나누면 된다 (9장 Q3).
- 방산망 안이지만 통신은 평문 HTTP 가 된다. 사내 인증서를 받을 수 있으면 HTTPS 로 띄운다 (uvicorn 기본 기능, 반입 0).

## 5. 저장과 동시 편집

**'고침 → 영향 미리 보기 → 저장'** — v0.4 가정 편집이 그대로 편집 화면이 된다.

1. 화면에서 고치면 저장 전 '가정' 상태로 쌓인다. JS 엔진이 날짜·주경로·완료일 변화를 바로 보여 준다.
2. '저장' 을 누르면 변경 묶음이 서버로 간다. 서버는 권한 → **내가 본 뒤로 남이 그 업무를 고쳤는지**(`rev`) 확인 → 반영 → 전체 다시 계산 → 이력 기록을 한 트랜잭션으로 한다.
3. 겹쳤으면 저장을 거절하고 '그 사이 이렇게 바뀜' 을 보여 준다 (덮어쓰지 않음). 모듈이 달라 실제로 겹칠 일은 드물 것으로 본다.
4. 다른 사람 화면은 몇 초마다 '바뀐 것 있나' 를 물어 받아 간다 (전체 판 번호 `rev` 이후 바뀐 업무만). 실시간 소켓은 쓰지 않는다 — 단순하고 충분.

저장하지 않고 닫으면 가정은 그 브라우저에 남는다 (지금과 같음). '가정만 해 보고 버리기' 도 그대로 된다.

## 7. 엑셀·온톨로지와의 관계

- **들여오기(1차본, 한 번)**: 지금 `read_wbs` → uid 부여 → `start_floor`·`relax_days` 계산 → 들여오기 보고서(검사 건수, 날짜 이동 0 확인).
- **내보내기**: 전체·모듈별, 지금 양식 그대로 (들여온 원본의 머리글·서식을 틀로 씀). 숨은 열에 uid 를 넣어 2단계 '엑셀로 고쳐 온 것 들여오기' 때 줄을 맞춘다.
- **인명 칸(작성자 등)**: 지금 규칙은 읽지도 않는다 → 내보낸 엑셀에서는 **빈 칸**이 된다. 유지가 필요하면 결정이 필요 (9장 Q2).
- **요약 줄의 Man Hours**: 하위 합으로 늘 계산한다. 원본에서 적힌 값 ≠ 아래 합(C12)이던 줄은 들여오기 보고서에 적고 합으로 바꾼다 (9장 Q4).
- **TTL·보고서**: 판을 확정할 때(그리고 원할 때) 만든다. IRI 를 uid 기준으로 바꿔 **판이 달라도 같은 업무는 같은 IRI** — docs/01 의 '고유 ID' 숙제가 풀린다. Tool·워크플로 온톨로지 연계의 발판.
- **백업**: SQLite 온라인 백업(표준 라이브러리)으로 매일 + 판 확정 때 다른 폴더에 사본, 최근 n개 보관. 서버 PC 가 망가져도 사본 파일 하나로 복구.

## 8. 구현 순서 (단계마다 사내에서 돌려 볼 수 있게)

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **S1 저장소** | DB 스키마 · `import`(엑셀→DB) · `export`(DB→엑셀) · DB→`Wbs` 변환. 서버 없음 | 합성 엑셀 → DB → 엑셀이 칸 단위로 같음 · 날짜 이동 0 · 검사·주경로 결과가 지금과 같음 |
| **S2 읽기 서버** | 서버 기동 `.bat` · 역할 계정 로그인 · 지금 화면 4개를 서버 데이터로 | 여러 브라우저에서 같은 화면, 조회자 권한 |
| **S3 칸 고치기** | 가정 → 저장 · 권한 · 겹침 거절 · 이력 · 다른 화면 반영 · 검사 화면 | 두 역할로 동시에 고쳐 보는 테스트 · JS 미리 보기 = 서버 결과 |
| **S4 줄 편집** | 표 편집 화면 · 추가·삭제·이동 · 선행 고르기 | 번호·WBS 코드 자동, 선행 안 깨짐 |
| **S5 협업** | 수정 요청 · 판 확정 · 모듈별 내보내기 · 백업 · (방식이 정해졌으면) 사내 계정 어댑터 | docs/04 1단계 전부 |

S1 은 지금 도구(v0.4)에 영향이 없고 서버도 필요 없다 — 답을 기다리는 동안 먼저 할 수 있다.

## 9. Leo 확인 질문

- **Q1. 사내 계정 연동 방식** — 사내가 무엇을 제공하는지 알아봐 주실 것: En-genius 플랫폼은 로그인을 어떻게 하나(플랫폼 개발자에게) · 인증 서버(OIDC/SAML) 등록이 되나 · Windows 로그인 계정을 그대로 쓰나. 답 전에는 역할 계정으로 진행.

## 11. S2 읽기 서버 (2026-11-12)

Leo 확인: 사내 `.venv` 에 **starlette 1.3.1 · uvicorn 0.51.0** 있음 → 새 반입 0 으로 진행. 개발 PC(1.7.0·0.54.0)와 **사내 판 그대로 만든 venv** 양쪽에서 테스트 통과.

**만든 것**
- `server.py` — 지금 보기 HTML(template_v3)을 그대로 쓰고 데이터만 서버에서 (`data.js`). DB 판(txn 번호)이 바뀔 때만 다시 계산해 둠 (합성 12,827행 약 2초, 그 뒤는 캐시).
  머리줄에 역할·판 번호·'엑셀 내려받기'(그 판을 원본 양식으로)·로그아웃, 30초마다 '새 판이 있음' 확인. 가정 편집은 그 브라우저 안에서만 (저장은 S3), 변경 목록 내려받기 단추는 숨김.
- `auth.py` — 역할 계정: 로그인 ID(영문) · 역할 이름(이력에 남는 것, 사람 이름 금지) · 종류 admin/leader/viewer · 모듈(리더). 비밀번호는 PBKDF2-SHA256 해시,
  로그인 토큰은 SHA-256 해시만 DB 에. 12시간 만료. 비밀번호를 바꾸거나 역할을 끄면 그 역할의 로그인이 끊긴다. 같은 주소에서 10분에 5번 틀리면 10분 막음.
- 권한: 모든 역할 = 보기·엑셀 내려받기, 관리자 = 역할 목록(`api/roles`). 쓰는 길은 아직 없다.
- 명령: `role add|list|passwd|off|on` · `serve [--host] [--port 8100]`. `.bat`: `scripts\serve.bat`(사내망 전체 — 0.0.0.0:8100) · `scripts\role.bat`.
- 폼은 직접 읽는다 (python-multipart 불필요), 세션은 DB 에 (itsdangerous 불필요). 화면 보안 머리(CSP·frame 금지·nosniff), 쿠키 HttpOnly·SameSite=Strict.

**사내에서 해 볼 순서**: `import.bat` 으로 DB → 명령 창에서 `scripts\role.bat add admin1 --label "관리자 1" --kind admin` (비밀번호 물어봄) →
`serve.bat` → 서버 PC 브라우저 `http://127.0.0.1:8100/` → 다른 PC 에서 `http://<서버 PC IP>:8100/`.
처음 띄울 때 Windows 방화벽이 네트워크 허용을 물을 수 있다 — 사내 보안 정책에 따라 Leo 가 판단 (개인 네트워크만).
포트 8100 은 플랫폼(8095)과 겹치지 않게 고른 기본값 — `--port` 로 바꿀 수 있다.

**확인 안 된 것**: 다른 PC 에서 접속(개발 PC 는 127.0.0.1 만 시험) · 사내 방화벽 · 20~30명 동시 접속 속도. 평문 HTTP 라 비밀번호가 망을 지난다 — 사내 인증서를 받으면 HTTPS(uvicorn 옵션)로.

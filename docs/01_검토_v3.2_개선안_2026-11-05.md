# WBS 온톨로지 v0.1 + 보기 v3.2 검토와 개선안 (2026-11-05, Fable)

검토 범위: 저장소 전체 (`parse.py`·`analyze.py`·`rdfout.py`·`report.py`·`viz.py`·`template_v3.html`·`synth.py`·설정·테스트·스크립트·README).
방법: 코드 정독 + 합성 WBS 12,827행 빌드(pytest 21 통과, 25.6초 중 TTL 쓰기 23초) + 브라우저에서 보기 HTML 속도 측정 + 사내 피드백(CLAUDE.md 11-04) 대조.
실제 WBS 는 보지 않았다 — 사내 숫자(업무 12,825·선행 11,949·레벨 수)만 근거로 쓴다.

## 0. 한눈에

**상태**: 읽기·검사·그래프 계산·TTL·보고서·보기 HTML 이 한 번에 돌고, 심은 문제를 전부 찾으며, 보기 HTML 은 피벗 방식으로 Leo 요구 (가)~(라) 를 다 받는다.
코드는 짧고(1,756줄) 외부 의존 0, 인명 규칙·폐쇄망 규칙을 지킨다. **기반은 튼튼하다.** 아래는 그 위에서 고칠 것이다.

**가장 중요한 발견 — 사내 피드백 4건 중 3건은 WBS 쪽이 아니라 도구 쪽에서 받을 수 있다** (2장 F1~F3):
마일스톤(0일)이 1일 막대로 그려짐 → ▼ 표시 · 요약 행 날짜와 하위 범위의 불일치는 검사가 없어서 안 보임 → 검사 C11 + '단계 요약' 시트 ·
키 마일스톤은 하부 ▼ 를 요약 행에 끌어올리면 됨. 이 셋은 작다(반나절).

**두 번째 — 계산이 엑셀 날짜를 전혀 안 쓴다** (F4): '가장 긴 사슬' 은 기간 합의 위상 계산이라 MS Project 가 보여 주는 주경로와 다를 수 있고, 사람들은 그 차이를 "틀렸다" 로 읽는다.
선행 간선마다 **엑셀 날짜로 잰 간격(여유 일수)** 을 계산하고 '빡빡한 사슬(간격 0)' 을 따로 보이면 MS Project 와 맞는 그림이 나온다 (합성에서는 FS 9,461건 중 8,905건이 빡빡함).

**세 번째 — IRI 가 A열 번호인데 MS Project 의 ID 는 행을 끼우면 다시 매겨진다** (F6). '고유 ID' 열을 내보낼 수 있으면 그것으로 바꿔야 판을 넘어 같은 업무를 가리킬 수 있다 — Leo 확인 필요 (Q1).

권장 순서: **묶음 1(피드백 직결) → 묶음 2(날짜 계산) → 묶음 3(속도)** 까지가 다음 판 v0.2. 온톨로지 다듬기(묶음 4)는 Q1·Q4 답을 받은 뒤.

## 3. 개선안 (묶음별, 권장 순)

### 묶음 1 — 사내 피드백 직결 (작음, 반나절) ← 먼저

1. **마일스톤 ▼** (F1): 잎이고 기간 0(또는 시작=완료)이면 간트·시간표에서 막대 대신 ▼(회색, 고른 것은 색). 범례 한 줄. TTL 에 `wbs:isMilestone true`.
2. **하부 마일스톤 끌어올리기** (F3): 상자(레벨 n 요소) 행에 그 아래 마일스톤을 작은 ▼ 로 같은 행에 찍고 hover 에 이름·날짜. 많으면 지저분하니 빠른 보기 옆 토글 '하부 마일스톤' (기본 켬, 상자 300 넘으면 끔). 어느 것이 '키' 인지는 WBS 가 안 알려 주므로 **이름 규칙이 있으면 설정** `milestone_key_pattern` (Q3).
3. **검사 C11 '요약 날짜 ≠ 하위 범위'** (F2): 요약 행에 날짜가 있고 하위(날짜 있는 것) min 시작·max 완료와 다르면 알림, 내용에 두 값. 보고서 '검사' 시트·② 검사 탭에 자동으로 나옴. 간트 요약 상자는 **하위 범위로 막대를 그리고** 엑셀 자기 날짜가 다르면 가는 선으로 겹쳐 보임.
4. **'단계 요약' 시트** (F2): Lv3 요소마다 — 구성품·최상위·단계 이름 · 엑셀 시작·완료 · 하위 범위 · 차이(일) · 하위 업무 수 · MH 합 · 마일스톤 수 · 밖에서 들어오는/나가는 선행 수. 사내에서 "단계 기간이 왜 이러냐" 를 바로 찾는 표. Lv4 판도 같은 모양으로.
5. **간트 '밖' 열** (F5): 왼쪽 표에 `←n / n→` 열(범위 밖에서 오는/나가는 선행 수), 누르면 패널에 그 목록(지금 패널의 '선행/후속 원본 행' 과 같은 것). 토막 상자는 안 그린다 (간트 행 구조를 지킴).
6. **SS·FF 앵커** (F9): SS 는 선행 시작→후속 시작, FF 는 선행 완료→후속 완료, SF 는 선행 시작→후속 완료.
7. **창 보호** (F10): `fit()` 에서 너비·높이 0 이면 그리지 않고 다음 resize 에서 맞춤 · `#canvasWrap{min-height:260px}` · 조작 줄 2줄로 압축(거르기 버튼은 'Lv1 전체' 처럼 짧게).

### 묶음 2 — 날짜 기준 계산 (중간, 반나절~하루)

8. **간선 날짜 간격** (F4): 간선마다 `gapDays` = 후속 쪽 사건 날짜 − 선행 쪽 사건 날짜(관계 종류별 끝 선택) − 지연, 평일로. FS 예: `weekdays_between(선행 완료, 후속 시작) − 2 − 지연`. 음수 = 날짜가 선행을 어김(= C05 와 일치), 0 = 빡빡, 양수 = 여유.
   TTL `wbs:gapDays`, 보고서 '업무' 시트에 '선행 중 최소 간격', 패널의 선행 목록에 `여유 n일`.
9. **날짜 기준 빡빡한 사슬**: 간격 ≤ 0 인 간선만으로 기간 합 최장 경로 (지금 `cpm` 과 같은 알고리즘, 간선만 다름). 보기에서 '가장 긴 사슬' 체크 옆에 '날짜로 빡빡한 사슬' 체크. 둘이 다르면 그 자체가 정보(제약·달력·손 날짜).
   보고서 요약에 두 사슬의 길이와 겹치는 업무 수. **CPM 은 그대로 두되 이름을 '기간 합 최장 사슬(달력 없음)' 로 분명히** — 지금 이름 '가장 긴 사슬' 이 MS Project 주경로로 읽힌다.
10. **기간 보완** (F8): 기간 없음 + 날짜 있음 → 평일 수로 보완하고 `durationFromDates true` 표시. 요약 통계에 '기간 없는 잎 n'.
11. **MH·투입인력 보완 규칙** (F8, Q2 답 뒤): 잎 합이 0 이고 자기 값이 있으면 자기 값. 보고서에 '어느 레벨 값인지' 열.
12. **run_log 에 레벨 수** — Leo 가 손으로 세어 보냈던 `Lv1 10 · Lv2 19 …` 를 `levels` 로 넣는다 (반출 가능 숫자). 마일스톤 수·기간 없는 잎 수·C11 건수도.

### 묶음 3 — 속도 (작음)

13. **TTL 손 직렬화** (F7): rdflib 그래프를 만들지 않고 Turtle 문자열을 바로 쓴다 (업무 순서대로, 접두 선언 한 번). 예상 2~3초. 테스트는 그대로 rdflib 로 다시 읽어 SPARQL 로 검산(지금 테스트 그대로). 대안은 `format="nt"` (1초, 읽기 나쁨) — 손 Turtle 권장.
14. **선택은 다시 그리지 않기** (F11): `select()` 가 행·막대 class 와 선 svg 만 바꾸도록. Lv6 전체에서 클릭 0.8초 → 즉시.

### 묶음 4 — 온톨로지 다듬기 (Q1·Q4 답 뒤)

15. **고유 ID** (F6, Q1): 엑셀에 '고유 ID' 열이 있으면 `columns.uid` 로 읽어 IRI `egid:WBS-U<고유ID>`; 없으면 지금처럼 A열. 판 간 이어받기는 이것이 있어야 레지스트리 없이도 된다.
16. **TTL 슬롯 추가** (F14): `isSummary`·`isMilestone`·`moduleName`·`phaseName`·`topTaskName` (derived 에, 분야 이름과 같이). 술어 수 5개 늘어남, 비용 0.
17. **산출물 노드 의미** (F15, Q4): 권장 = 지금처럼 **유형(이름) 공유 노드** 유지하되 `wbs:producedIn <구성품>` 을 더해 구분 가능하게. 자료 조사 유형(`engenius-data-inventory` form.yaml TYPES)과 잇는 건 그 다음.
18. **LinkML 스키마** — Tool 온톨로지처럼 `schema/wbs.yaml` 로 옮기고 SHACL 생성. 지금은 코드 안 RDFS 로 충분하므로 **M4 뒤·연계 때**. 지금 하지 않는다.

# 월별 공수 보기 — 구현 검토 (2026-11-11, Fable)

요청 (Leo 2026-11-11): **월별 공수를 막대그래프로**, 막대를 **두 번 누르면 그 달의 모듈(Lv1)별 공수 구성**.
이 문서는 설계 검토다 — 코드는 아직 고치지 않았다. 숫자는 전부 합성 WBS(12,827행) 시험 계산.

## 0. 결론

- **할 수 있고 작다.** 필요한 값(업무별 시작·완료·Man Hours)은 이미 보기 HTML 안에 들어 있다. 새 패키지 0, 반나절 규모.
- 정해야 하는 것은 그리기가 아니라 **계산 규칙 2개** — (1) 어느 행의 MH 를 쓰나 (2) 한 업무의 MH 를 달에 어떻게 나누나.
- 시험 계산: 합성 10,379 하위 업무 → 120개월 × 7 모듈, 배분 0.2초, **월 합계 = MH 총합 (4,466,488) 일치**.

## 1. 계산 규칙

### 1-1. 어느 행의 MH 를 쓰나 — '가장 아래에 적힌 값'

MS Project 는 요약 행에 하위 합을 자동으로 적는다. 요약과 하위를 다 더하면 두 배가 된다.

- 어떤 업무 아래에 MH 가 적힌 하위가 **하나라도 있으면** 하위 것만 쓴다. **없으면** 그 업무 자신의 MH 를 쓴다.
  → MH 가 Lv6 에 있든 Lv5 에만 있든 섞여 있든 한 규칙으로 받는다 (검토 문서 Q2 의 답을 기다리지 않아도 된다).
- 요약 행 MH ≠ 하위 합이면 **검사 C12** 로 알린다 (차이는 그래프에 넣지 않는다 — 어느 달인지 알 수 없다).

### 1-2. 달에 어떻게 나누나 — 시작~완료의 평일에 고르게

- 업무 MH ÷ (시작~완료 사이 월~금 날 수) 를 하루치로 보고 달마다 더한다. MS Project 기본(균등 배분)과 같은 가정.
- 마일스톤(0일)·하루짜리 → 그 날이 속한 달에 전부.
- 날짜가 없거나 거꾸로인 업무 → 그래프 밖 **'날짜 없음' 칸**에 따로 (건수·MH). 숨기지 않는다.
- **모르는 것**: 공휴일·사내 달력, 업무별 배분 곡선(앞쪽 몰림 등). 그래서 화면에 '평일 균등 배분(달력 없음)' 이라고 적는다.
  MS Project 의 '리소스 사용 현황' 과 달 단위로 몇 % 다를 수 있다 — 총합은 같다.

## 2. 화면

```
[보기] [검사] [공수]                          단위: MH | M/M     묶음: 월 | 분기 | 연
 범위: 전체 (거르기를 따름)                    총 4,466,488 MH · 120개월 · 최고 2031-07

  █
  █ █     █
█ █ █ █ █ █ █ █ …                              ← 한 가지 색. 가리키면 그 달 값
'27        '28        '29                      ← 연 눈금 (엑셀 틀 고정처럼 위에 고정)

 ── 막대를 두 번 누르면 ──
 ← 뒤로   2031-07 · 71,512 MH
 모듈 A  ████████████████  28,400  40%
 모듈 B  ██████████        17,900  25%          ← 큰 순서 가로 막대, 한 가지 색
 모듈 C  ██████            10,700  15%
 …                                             ← 모듈을 또 두 번 누르면 Lv2 → Lv3 …
```

- **탭 하나 추가** ('공수'). 기존 보기·검사는 그대로.
- **구성은 가로 막대 순위** (권장). 원그래프·10색 누적 막대는 쓰지 않는다 — 모듈 10개면 색 구분이 안 되고, 여러 색을 피하자는 기존 방침과도 맞다.
- **두 번 누름 = 안으로** 는 지금 보기와 같은 약속. 뒤로·바깥으로·위치 줄(v3.2)도 같은 방식, 주소(#)에 상태 저장.
- **모듈을 한 번 누르면** 위 월별 막대에 그 모듈 몫이 진한 색으로 겹쳐 보인다 (회색 전체 + 진한 한 색, 두 톤). '이 모듈은 언제 바쁜가'.
- **거르기 연동**: 보기 탭에서 고른 범위(단계·분야 등)를 그대로 따른다 + '전체' 버튼. 예: 상세설계 단계만의 월별 공수.
- 좁은 창: 막대 최소 폭 3px 를 못 지키면 자동으로 분기 묶음.

## 3. 구현 위치

| 곳 | 무엇 | 크기 |
|---|---|---|
| `template_v3.html` | 공수 탭 — 배분 계산(JS)·막대·구성·탐색 | 약 150줄, +6 KB |
| `analyze.py` | 같은 배분을 파이썬으로 (`workload()`), 검사 C12 | 약 60줄 |
| `report.py` | 시트 **'월별 공수'** (행 = 달, 열 = 모듈, 합계) — 엑셀로 가져가 쓰기 | 약 25줄 |
| `viz.py` | 월 합계 검산값을 데이터에 넣음 (JS 계산과 맞는지 화면이 스스로 확인) | 5줄 |
| `config/wbs.yaml` | `hours_per_man_month` (M/M 환산) | 1줄 |
| `synth.py`·tests | 요약 MH 불일치·날짜 없는 업무·마일스톤 사례 주입, 테스트 5개 | 약 60줄 |

- 계산을 **화면(JS)에서** 하는 이유: 거르기를 따라가려면 미리 계산한 표로는 안 된다. 1만 건 배분은 수십 ms.
- 파이썬·JS 두 벌이 생기므로 **불변식 테스트**: 월 합계 = 쓰인 MH 총합, 파이썬 월 합계 = JS 월 합계.
- TTL 에는 넣지 않는다 (파생 집계이고 판마다 다시 계산). 필요해지면 derived 에 월 노드로.

## 4. 걸리는 점

1. **실제 WBS 의 MH 품질을 모른다.** 빈 칸이 많으면 그래프가 '공수' 가 아니라 '적힌 공수' 다 → 탭 머리에 **MH 가 적힌 업무 비율**을 늘 보여 준다.
2. **투입인력(명) 열과 MH 가 안 맞을 수 있다** (명 × 기간 × 8 ≠ MH). 이번엔 MH 만 쓴다. 인원 기준 그래프는 다음.
3. **합성 데이터가 너무 깨끗하다** — 요약 MH = 하위 합, 날짜 누락 0, 마일스톤 0. 사례를 주입해야 규칙이 시험된다 (3장).
4. 검토 문서 F8(MH 를 잎에서만 합산)과 같은 뿌리 — 1-1 규칙을 간트 쪽 MH 표시에도 같이 쓴다.
5. 합성의 최고 달 71,512 MH(160h 기준 약 447명)는 구조 시험용 숫자일 뿐이다.

## 6. Leo 결정 (2026-11-11)

- **W1** MH 만 우선 (M/M 전환은 넣지 않는다 — `hours_per_man_month` 설정도 이번엔 없음).
- **W2** 가로 막대 순위. **W3** 보기 탭 범위를 따름 + '전체' 버튼.
- **W4** 검토 문서(docs/01) **묶음 1 과 한 판(v0.2)** 으로 — 반입 한 번.
- **y축**: 보이는 범위의 **월 최대 MH 에 맞춘다** (그 위의 깔끔한 눈금값 — 1·2·2.5·5 × 10ⁿ — 으로 올림, 눈금 4~5개).
  거르기·월/분기/연 묶음을 바꾸면 다시 맞춘다. 모듈 몫을 겹쳐 볼 때는 전체 축을 그대로 둔다 (전체 대비 크기가 보이게);
  몫이 너무 작아 안 보이면 '이 모듈에 맞춤' 버튼으로 그 모듈 최대치에 맞춘다. 구성 가로 막대도 그 달의 가장 큰 모듈에 맞춘다.

## 7. 구현 결과 (v0.2, 2026-11-11)

- 검토 문서 docs/01 **묶음 1 전부** + 월별 공수를 한 판으로. 코드: `workload.py`(새) · `analyze.py`(C11·C12·하위 범위) · `report.py`(단계 요약·분야 요약·월별 공수 시트) ·
  `template_v3.html`(마일스톤·요약 막대·밖 열·SS/FF·창 보호·③ 탭) · `synth.py`(마일스톤 201·C11·C12·날짜 없는 업무 심음) · `rdfout.py`(`wbs:isMilestone`).
- 3장 표와 다른 점: M/M 전환·`hours_per_man_month` 는 W1 에 따라 넣지 않음. 모듈 몫 겹쳐 보기는 Lv1 뿐 아니라 **구성 표의 어느 행이든**(안으로 들어간 레벨에서도).
  기간 묶음은 월·분기·연 버튼 + 창이 좁으면 자동으로 굵게. 요약 행 MH 불일치(C12)는 그래프에 넣지 않고 검사로만.
- 검증: pytest 23 (손으로 셈한 9행 WBS — Lv2 에만 적힌 MH·Lv2·Lv3 섞임·주말만 업무·날짜 없음·C11·C12 — 와 합성 12,827행의 불변식: 달 합 + 날짜 없음 = 쓴 MH,
  월별 공수 시트 합계, 단계 요약의 완료 차이 = 심은 7일, isMilestone 수). 브라우저(헤드리스 Edge 1600×900): 간트 ▼·▽·밖 열, 공수 탭 막대 두 번 누름 → 구성 → 겹쳐 보기 → 안으로 2단 → 맞춤 → 뒤로·바깥으로,
  JS 월 합계 = 파이썬 월 합계(화면 '일치 ✓'), 콘솔 오류 0, 1만 건 공수 계산·그리기 10 ms.
- **실제 WBS 로는 아직 안 돌림** — 사내에서 볼 것: ③ 탭 아래 줄의 'MH 쓴 행(레벨별)' · 'MH 없는 하위 업무' · '일치 ✓', 검사 C11·C12 건수 (run_log 에 레벨별 수·마일스톤 수·MH 쓴 행 수가 들어감 — 숫자만 반출 가능).

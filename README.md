# En-Genius WBS 온톨로지 (engenius-wbs-ontology)

MS Project 로 만든 **WBS 엑셀**(약 12,800행)을 읽어 업무 사이 **선행 관계 그래프**를 만들고, 검사·계산·보고서·보기 HTML 을 낸다.
Tool 온톨로지·워크플로 온톨로지·자료 조사의 형제 저장소. 이 PC 에서는 **가짜 WBS** 로만 만들고 검증한다 — 실제 WBS 는 사내에서만 돌린다.

## 읽는 엑셀 모양

| 칸 | 뜻 | 읽는 법 |
|---|---|---|
| 번호 (A) | 업무 번호 — 선행 칸이 이 번호를 가리킨다 (엑셀 행 번호 아님) | 정수 |
| WBS (B) | `1.2.1.1.2.1` — 마디 수 = 레벨, 마지막 마디를 뗀 코드 = 상위 | 레벨·트리의 정본 |
| 작업 이름 (C) | 앞 띄어쓰기 = 들여쓰기 | 이름 + 들여쓰기 검사(P07) |
| 기간 (D) | `120 일` · `<120 일 >` · `12일?`(추정) · `3주` | 근무일 |
| 시작·완료 (E·F) | 글자 `27-01-01 (금)` · `39-12-02(금)` | 날짜 + 요일 검사(P09) |
| 선행 작업 (G) | `12,15FS+10일,20FF` — 관계 FS(기본)·SS·FF·SF, 지연 ±일·주·개월 | **핵심** |
| 후속 작업 (H) | MS Project 가 낸 G 의 역방향 | 적재하지 않고 검산만(C07) |
| 작성자 (I) | — | **읽지 않음** (인명) |
| 투입인력(명)·Man Hours (J·K) | 숫자 | 합계용 |
| 산출물 (L) | 주로 Lv5, 쉼표·줄바꿈으로 여럿 | 산출물 노드 |

헤더는 **이름으로** 찾는다 (`config/wbs.yaml` — 위 15행 안, 제목 행이 있어도 됨). 레벨: Lv1 구성품 · Lv2 최상위 업무 · Lv3 개발 단계 · Lv4 기술 분야 · Lv5 상위 기술 업무 · Lv6 하위 기술 업무.

## 명령

```
python -m engenius_wbs build <WBS.xlsx> [--sheet 시트] [--out 폴더]     # 사내: WBS 엑셀을 scripts\build.bat 에 끌어다 놓기
python -m engenius_wbs apply <WBS.xlsx> <변경.json> [--out 폴더]      # 가정 편집 반영 → 새 판 엑셀 (scripts\apply.bat 에 두 파일을 함께 끌어다 놓기)
python -m engenius_wbs synth [--rows 12827]                           # 가짜 WBS → data/synthetic/wbs_synthetic.xlsx
python -m pytest                                                     # scripts\selftest.bat
```
실행: 형제 저장소 Tool 온톨로지의 `.venv` 파이썬 + `PYTHONPATH=src` (`scripts\env.bat` 이 맞춰 준다). 새 패키지 0 (openpyxl·rdflib·pyyaml).

## 사내(방산망) 설치

1. GitHub `aerogyu/En-genius-WBS-Ontology` → **Code → Download ZIP** (`En-genius-WBS-Ontology-main.zip`, 약 1 MB — 합성 WBS 엑셀 포함) → 반입.
2. 풀어서 **Tool 온톨로지와 같은 부모 폴더**에 둔다 — 예: `C:\EnGenius\engenius-wbs-ontology` (옆에 `C:\EnGenius\engenius-tool-ontology` 가 있어야 한다).
   다른 곳이면 `scripts\env.bat` 의 `TOOL_ONTO_DIR` 를 Tool 온톨로지 폴더로 고친다. 따로 설치할 것 없음 (그쪽 `.venv` 를 쓴다).
3. `scripts\selftest.bat` 더블클릭 → `28 passed` · `rc=0`.
4. WBS 엑셀(.xlsx — 첫 시트를 읽는다)을 `scripts\build.bat` 위에 끌어다 놓기 → 출력 폴더의 `wbs_view.html`(브라우저)·`report.xlsx`.
   WBS 가 첫 시트가 아니면: `scripts\env.bat` 실행 뒤 `"%PY%" -m engenius_wbs build <파일> --sheet <시트 이름>`.
5. `P01 헤더를 찾지 못함` 이면 헤더 문구가 별칭에 없다 → `config\wbs.yaml` 을 `data\real\config\wbs.yaml` 로 복사해 `columns` 에 그 문구를 더한다.
6. **WBS 고치기 (가정 편집)**: 보기에서 하위 업무를 고르고 오른쪽 패널 '✎ 가정 편집' 에서 기간·시작·선행·이름·MH 를 바꾸면 날짜·주경로가 바로 다시 계산된다
   (고친 것은 브라우저에 남아 다시 열어도 그대로). ④ 주경로 탭 '변경 목록 내려받기' → 받은 `.json` 과 **원본 WBS 엑셀을 함께** `scripts\apply.bat` 위에 끌어다 놓기
   → 원본 옆에 `<원본>_수정_v01.xlsx`(원본 형식 그대로, 바뀐 칸만 고침, 원본은 그대로) + `.changes.json`(무엇을 고쳤나), 이어서 그 파일로 build.
   날짜는 '간격 유지' 규칙으로 다시 짠다 — 선행에 바로 밀리던 업무는 따라 움직이고, 여유가 있던 업무는 여유를 다 쓸 때까지 그대로, 새로 더한 선행은 미는 쪽으로만.
   선행을 지워도 저절로 당겨지지 않는다 (당기려면 시작을 고친다). 행 추가·삭제는 아직 안 된다.
7. 밖으로 가져올 수 있는 것은 `run_log.json` 의 건수(문제 코드별 건수·업무 수·걸린 시간)뿐 — 보고서·HTML·TTL 은 업무 이름이 든 사내 자료.

## 산출물 (`output/<시각>/`)

| 파일 | 내용 |
|---|---|
| `wbs_view.html` | 보기 (v3, 피벗 방식) — **거르기**(레벨마다 이름 여러 개 체크 + 트리 체크로 손으로 고른 묶음) × **묶기**(상자 = 어느 레벨) × **줄 나누기**(없음 · Lv1~4 이름별 · 고른 항목별) × **배치**(간트(기본) · 시간표 · 흐름도). 간트 = 한 행 한 상자, 왼쪽 표(WBS·이름·시작·완료·기간)와 위 눈금 틀 고정, 막대 = 실제 기간, 줄 나누기는 접히는 머리 행, 행 순서 WBS 순/시작일 순, Ctrl+휠 가로 확대. **선 보기** 끔 · 고른 것만(기본 — 누른 상자의 앞뒤 사슬만) · 넘겨받기만 · 전부. 빠른 보기 4개(단계 하나·분야별 줄 / 분야 하나·모든 단계 / 한 레벨 전체·줄 없음 / 트리에서 고른 것), 아래에 '지금 보기' 한 줄 문장, '보기 주소 복사'(같은 HTML 을 가진 사람에게 주소만 보내면 같은 화면). 거른 범위 밖 출입은 점선 토막, 한 번 누름 = 앞(보라)·뒤(초록) 강조 + 오른쪽 패널(요약·넘겨받기·가장 긴 사슬·원본 선행 행), 두 번 누름 = 그 경로로 거르기. 이름은 자르지 않음, 휠 확대·끌어 이동, 연도 눈금 틀 고정. ② 검사 탭. **마일스톤 ▼**(묶음 행엔 그 아래 마일스톤 ▽), 묶음 막대 = 하위 범위(엑셀 요약 날짜가 다르면 빨간 가는 선), 간트 '밖 ←/→' 열. **③ 월별 공수 탭** — 월/분기/연 Man Hours 막대(세로축 = 보이는 범위 최대치), 막대 두 번 누름 = 그 달의 구성품별 순위, 행 두 번 누름 = 한 레벨 안으로, 행 누름 = 그 몫을 위 그래프에 겹쳐 보기. **④ 주경로 탭** — 무엇이 사업 완료를 쥐고 있나(레벨별 주경로 평일 합 · 시작 순 목록 · 구동 선행 · 다음 경로 여유), 간트 빨강/노랑 막대·여유 열·빠른 보기 주경로만. 외부 JS 없음 |
| `report.xlsx` | 요약 · 검사 · **주경로**(시작 순 · 총 여유 · 구동 선행) · **단계 요약·분야 요약**(엑셀 날짜 vs 하위 범위·차이·MH·마일스톤·밖 출입) · **월별 공수**(달 × 구성품) · 업무(레벨·구성품·단계·분야·선행/후속 수·앞쪽/뒤쪽 전체·CPM 이른 시작·여유·가장 긴 사슬) · 분야 행렬 · 분야 간 연결 · 가장 긴 사슬 |
| `wbs.ttl` | 엑셀에 적힌 것 — 업무(레벨별 클래스)·`wbs:partOf`·`wbs:precededBy`·선행 관계 노드(관계 종류·지연)·산출물 |
| `derived.ttl` | 계산한 것 — 앞쪽/뒤쪽 전체 수·날짜 기준 총 여유·주경로·선행 간격·분야 간 흐름, provenance(규칙 판·생성 시각) |
| `run_log.json` | 건수·문제 코드별 건수·걸린 시간 (값·이름 없음) |

**실제 WBS 로 만든 산출물은 업무 이름이 든 사내 자료다** — 밖으로 가져가지 않는다. `run_log.json` 은 건수뿐이다.

그래프: C01 없는 번호를 선행으로 · C02 자기 자신 · C03 순환 · C04 상위 묶음이 선행에 걸림 · C05 선행 조건과 날짜 어긋남 · C06 기간과 날짜 불일치(휴일 모름) ·
C07 H열 ≠ G 역방향 · C08 고립 하위 업무 · C09 시작 > 완료 · C10 상위 묶음 ↔ 그 하위 업무 사이 선행 ·
C11 요약 날짜 ≠ 하위 범위 · C12 요약 Man Hours ≠ 하위 합.

**월별 공수 규칙**: 아래(하위)에 Man Hours 가 적힌 업무가 하나라도 있으면 아래 것만, 없으면 자기 것 (MS Project 가 요약 행에 적는 합을 두 번 세지 않음).
한 업무의 MH 는 시작~완료 평일에 고르게 나눈다 — 휴일·사내 달력은 모름(근사, 총합은 같음). 날짜 없는 업무는 '날짜 없음' 으로 따로.

## 계산의 한계 (보수적으로)

- **주경로·총 여유는 엑셀에 적힌 날짜를 평일(월~금)로 잰 근사**다 — 휴일·사내 달력·제약 조건(SNET 등)·리소스 평준화는 모른다.
  총 여유 = 사업 마지막 완료를 늦추지 않고 밀릴 수 있는 평일 수, 주경로 = 여유 0 이하, 준주경로 = 5 평일 이하 (`config/wbs.yaml` `schedule`, 화면에서도 바꿈).
- 주·개월 단위는 주 5일·개월 20일로 바꾼다. `+50%` 같은 비율 지연은 0 으로 계산한다 (표기는 보존).
- 번호(A열) 는 같은 엑셀 판 안에서만 안정한 ID 다. 판을 넘는 이어받기(레지스트리)는 다음 판에서.
